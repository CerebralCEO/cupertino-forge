# 10 Haptics and sound

Source of truth: `tokens/feedback.json`.

## Apple's actual behavior

- iOS standard controls play haptics, not sounds (`[official]`): toggles, pickers, sliders at detents use selection (`UISelectionFeedbackGenerator`); long press uses impact (`UIImpactFeedbackGenerator`: `light`, `medium`, `heavy`, `soft`, `rigid` `[official]`); outcomes use notification (`UINotificationFeedbackGenerator`: `success`, `warning`, `error` `[official]`).
- Plain button taps have NO haptic in Apple apps (`[official]`/`[inferred]`). Do not add a buzz to every button.
- macOS UI is silent and has no haptics except Force Touch trackpad feedback (`NSHapticFeedbackManager`: `alignment`, `levelChange`, `generic` `[official]`).
- watchOS defines 9 `WKHapticType` patterns (`notification`, `directionUp`, `directionDown`, `success`, `failure`, `retry`, `start`, `stop`, `click` `[official]`) alongside `64 kbps` HE-AAC (`[official]`) media encoding.
- Audio session: use `AVAudioSessionCategory.ambient` (`[official]`) for UI sound effects so user music continues playing; sound assets remain `opt-in OFF` (`0.35` master gain, `40ms` throttle `[estimate]`).
- **Never stack haptic and sound on toggles (`[inferred]`):** play haptic when supported (`CfHaptics.supported` / mobile Web), and only fall back to toggle audio when haptic is disabled/unsupported.

## Haptic map (summary)

| Event | iOS | Android | Web |
|---|---|---|---|
| toggle, picker tick, segment change, slider detent | selection | TOGGLE_ON/OFF, SEGMENT_TICK | selection |
| long press opens menu | impact medium | LONG_PRESS | medium |
| pull to refresh threshold, swipe action threshold | impact light | GESTURE_THRESHOLD_ACTIVATE | light |
| drag snaps, sheet detent snaps | impact soft or light | SEGMENT_TICK | light |
| drop into place | impact rigid | CONFIRM | medium |
| success | notification success | CONFIRM | success |
| warning, destructive confirmed | notification warning | REJECT | warning |
| error | notification error | REJECT | error |

Implementation: web `lib/haptics.ts` (Android vibrate patterns, iOS Safari 18+ switch input trick inside user gestures, desktop no-op); Flutter `AppleHaptics` (HapticFeedback on iOS, HapticFeedbackConstants via channel on Android); Tauri: none (desktop).

## Sound policy

1. Sounds are OFF unless `.apple-design.json` has `"sounds": true`, and even then the app exposes a setting to turn them off.
2. Never ship Apple system sound files. Use the plugin's original synthesized sounds (`assets/sounds/*.wav`, generated by `scripts/synth-sounds.py`).
3. Allowed sound events: toggle, tap on primary actions, picker tick (throttled 40ms), success, error, send, refresh, custom keyboard keys. Nothing else.
4. Volume 0.35 master, respect system mute (web: only after first user gesture; mobile: ambient audio session so it never stops the user's music).
5. Sound and haptic for the same event are allowed only for success, error and send.

## Rules

- One feedback per event. Do not stack haptic and sound on toggles.
- Never feedback on scroll, hover, focus, or page load.
- Throttle repeated haptics (picker, slider) to one per detent.
- Always optional and respect OS settings.
