\# Mission: Cupertino Forge-এর Deep Research, Gap Analysis এবং Next-Level Upgrade Blueprint



তোর কাছে `cupertino-forge` নামের একটি Claude Code Plugin আগে থেকেই ইনস্টল করা আছে। এই Plugin-এর উদ্দেশ্য হলো যেকোনো ধরনের সফটওয়্যার প্রজেক্টের UI এবং UX-কে Apple-এর iOS 27 ও macOS 27 Design Language অনুসরণ করে যতটা সম্ভব নিখুঁতভাবে রূপান্তর করা।



প্রজেক্টটি Flutter Mobile App, Next.js Web App, React Application, Rust Desktop Application, Tauri App কিংবা অন্য যেকোনো প্রযুক্তিতে তৈরি হতে পারে।



\*\*তোর প্রথম কাজ হলো ইনস্টল করা `cupertino-forge` Plugin-টি সম্পূর্ণভাবে পরীক্ষা করা।\*\*



কোনো কিছু অনুমান করে কাজ শুরু করবি না। Plugin-এর প্রকৃত ফাইল, ডকুমেন্টেশন, Skills, Commands, Agents, Hooks, Scripts, Tokens, Adapters, Configuration এবং বিদ্যমান Implementation নিজে পরিদর্শন করবি।



শুধু README বা Documentation পড়ে সিদ্ধান্ত নিবি না। সম্ভব হলে প্রতিটি গুরুত্বপূর্ণ ফাইল এবং তার পারস্পরিক সম্পর্ক বুঝে নিবি।



এই মুহূর্তে কোনো কোড পরিবর্তন বা Implementation করবি না। প্রথমে সম্পূর্ণ Research, Technical Audit, Gap Analysis এবং Upgrade Roadmap তৈরি করবি।

\# ১. আমাদের চূড়ান্ত লক্ষ্য



আমরা `cupertino-forge`-কে এমন একটি Advanced Apple Design Engineering System-এ পরিণত করতে চাই, যেটা কোনো সফটওয়্যার প্রজেক্টের UI/UX বিশ্লেষণ করে সেটিকে Apple-এর Design Philosophy, Visual Language, Interaction Patterns এবং Motion Principles অনুসারে রূপান্তর করতে পারবে।



শুধু দেখতে Apple-এর মতো হলেই হবে না।



আমাদের লক্ষ্য:



\- Apple-এর Design Language-এর প্রতি সর্বোচ্চ Visual Fidelity।

\- iOS এবং macOS-এর Native Design Convention যথাসম্ভব অনুসরণ।

\- অত্যন্ত পরিশীলিত Layout, Typography, Spacing এবং Geometry।

\- যথাযথ Liquid Glass এবং Material Treatment।

\- Natural, Fluid এবং Context-aware Animations।

\- Native-feeling Interactions এবং Gestures।

\- Consistent Component Architecture।

\- Accessibility এবং Performance।

\- প্রতিটি Platform-এর নিজস্ব UX Convention অনুসরণ।

\- Automated Visual এবং Functional Quality Assurance।



একটি গুরুত্বপূর্ণ বিষয়: Apple-এর প্রকৃত Native Rendering, System API, SF Symbols, System Fonts, Haptics এবং Liquid Glass-এর কিছু আচরণ নির্দিষ্ট Apple Hardware ও Operating System-এর ওপর নির্ভরশীল।



তাই Android, Windows, Linux কিংবা Web-এ সবকিছুর 100% Native Apple Parity সম্ভব—এমন দাবি করা যাবে না।



বরং প্রতিটি Platform-এ যতটা সম্ভব উচ্চমানের Apple-inspired Experience তৈরি করতে হবে এবং কোথায় Native Parity সম্ভব, কোথায় Approximation প্রয়োজন, সেটা স্পষ্টভাবে চিহ্নিত করতে হবে।

\# ৫. Advanced Visual Quality Assurance System



এখানে বিশেষ গুরুত্ব দিতে হবে।

\- Reference Screenshot Comparison।

\- Pixel-level Difference।

\- Structural Layout Comparison।

\- Typography Comparison।

\- Color Difference Detection।

\- Spacing এবং Alignment Analysis।

\- Corner Radius Comparison।

\- Material এবং Transparency Analysis।

প্রয়োজনে SSIM, Perceptual Similarity, Image Difference এবং অন্যান্য উপযুক্ত Visual Comparison Technique নিয়ে Research কর।



একটি গুরুত্বপূর্ণ বিষয়:



শুধু Pixel Difference দিয়ে Visual Quality বিচার করা যাবে না। একই UI বিভিন্ন Browser, GPU, Font Rendering Engine এবং Operating System-এ সামান্য ভিন্নভাবে Render হতে পারে।



তাই False Positive কমানোর জন্য একাধিক Validation Method ব্যবহার করার সুপারিশ কর।



আমরা এমন একটি Workflow চাই:



1\. UI তৈরি।

2\. Screenshot Capture।

3\. Reference-এর সঙ্গে Comparison।

4\. Visual Issues শনাক্ত।

5\. Issue Report তৈরি।

6\. প্রয়োজনীয় সংশোধন।

7\. আবার Screenshot Capture।

8\. পুনরায় Comparison।

9\. Final Visual Audit।



কোনো Reference Screenshot না থাকলে Pixel-perfect Score বানিয়ে দেওয়া যাবে না। সেক্ষেত্রে Structural এবং Design-rule-based Audit করতে হবে।

Research Finding-গুলোকে নিচের শ্রেণিতে ভাগ কর:



\- Official: সরাসরি Official Documentation দ্বারা সমর্থিত।

\- Measured: বাস্তব পরীক্ষা বা Measurement দ্বারা প্রমাণিত।

\- Inferred: একাধিক নির্ভরযোগ্য তথ্য থেকে যৌক্তিকভাবে নির্ণীত।

\- Platform-dependent: নির্দিষ্ট OS, Hardware বা Framework-এর ওপর নির্ভরশীল।



কোনো Estimated Value-কে Official Apple Specification হিসেবে উপস্থাপন করবি না।



কোনো তথ্য পাওয়া না গেলে সেটি স্পষ্টভাবে উল্লেখ করবি।

3\. শুধু নতুন Feature যোগ করার জন্য নতুন Feature প্রস্তাব করবি না।

4\. Generic AI-generated Suggestions দিবি না।

5\. বাস্তব Technical Gap ছাড়া কোনো সমস্যা বানিয়ে দেখাবি না।

6\. একই Recommendation বিভিন্ন নামে বারবার লিখবি না।

7\. Official Apple Specification এবং অনুমানভিত্তিক Value আলাদা রাখবি।

8\. সব Platform-এ 100% Native Apple Experience সম্ভব—এমন দাবি করবি না।

9\. Accessibility এবং Performance-কে Secondary বিষয় হিসেবে বিবেচনা করবি না।

10\. Plugin-এর বর্তমান Architecture যতটা সম্ভব Preserve করে Upgrade-এর পথ খুঁজবি।

11\. প্রতিটি Recommendation বাস্তবে Implement করা সম্ভব কি না, তা বিবেচনা করবি।

12\. কোনো Testing সম্পন্ন না হলে সেটিকে Tested হিসেবে দাবি করবি না।

13\. Research-এর সময় প্রয়োজন অনুযায়ী Web Search এবং Official Documentation ব্যবহার করবি।

14\. শুধু Documentation নয়, বাস্তব Implementation এবং Testing Capability-ও যাচাই করবি।

15\. কোনো গুরুত্বপূর্ণ বিষয় যাচাই করা সম্ভব না হলে সেটিকে Unknown বা Unverified হিসেবে চিহ্নিত করবি।
